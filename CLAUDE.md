# Правила для работы в репозитории

Ripen — open source self-hosted слой каналов стабильности. Код, README, спецификация и ADR пишутся на английском, решения и исследования для владельца в `docs/` — на русском.

## Структура

- `packages/core` — доменная модель без ввода-вывода: каналы, договор канала, гейты.
- `packages/server` — HTTP-сервер на `node:http` и `node:sqlite`; `src/engine.ts` работает без Node (браузер, edge).
- `packages/sdk-js`, `packages/sdk-dart` — SDK для JavaScript и Dart/Flutter.
- `packages/elements`, `packages/dashboard` — веб-компоненты: выбор канала и отзыв, консоль релизов.
- `packages/cli`, `action.yml`, `action/ripen.mjs` — CLI и GitHub Action (бандл генерируется `pnpm build:action`, не править руками).
- `packages/openfeature` — провайдер OpenFeature (peer-зависимость, ADR 8).
- `apps/demo` — демо в браузере.
- `docs/spec.md` — модель и HTTP API. Меняешь поведение — обнови спецификацию в том же коммите.
- `docs/guide/` — руководства для пользователей, `docs/adr/` — архитектурные решения, `docs/research/` — исследование и решения на русском.
- Пользовательские изменения записывать в `CHANGELOG.md` в раздел «Unreleased».

## Код

- Без runtime-зависимостей (ADR 3). Новая зависимость — только с явного согласия владельца.
- TypeScript только со стираемым синтаксисом (`erasableSyntaxOnly`): без enum, namespace и parameter properties. Относительные импорты с расширением `.ts`.
- Проверки перед коммитом: `pnpm check` (типы, тесты, сборка, свежесть бандла экшена); при правке компонентов и консоли ещё `pnpm test:browser`, при правке Dart SDK — `pnpm test:dart`.

## Зависимости

- Ставить только версии, опубликованные не меньше 7 дней назад. pnpm это проверяет сам (`minimumReleaseAge` в `pnpm-workspace.yaml`), для остального (GitHub Actions, Docker-образы, бинарники) смотреть дату релиза вручную.
- Только известные пакеты из официального реестра. Перед добавлением проверять точное имя (тайпсквоттинг), автора и нужен ли пакет вообще. Без git- и URL-зависимостей.
- Настройки защиты в `pnpm-workspace.yaml` не ослаблять и не обходить (`--config.minimum-release-age=0`, `trustPolicy`, `onlyBuiltDependencies` и т. п.) без явного согласия владельца.
- Установка в CI и при проверках — `pnpm install --frozen-lockfile`. `pnpm-lock.yaml` меняется только вместе с `package.json` и попадает в тот же коммит.
- GitHub Actions подключать по полному SHA коммита с комментарием-тегом (`uses: owner/action@<sha> # vX.Y.Z`), только от известных авторов. Docker-образы — по digest.

## Секреты и доступы

- Никаких ключей, токенов и паролей в коде, коммитах, логах и комментариях. Сервер берёт секреты только из переменных окружения, не из аргументов командной строки.
- `.env*`, `*.pem`, `*.key`, файлы базы `*.db` в `.gitignore`; перед коммитом смотреть `git diff --cached` на предмет случайно попавших секретов.
- Не выводить секреты в консоль (`echo`, `set -x`, `env`, `cat` ключа).
- Нашёлся утёкший секрет — сразу сообщить владельцу: его надо отозвать и перевыпустить, одного удаления из истории мало.

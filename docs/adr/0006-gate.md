# 6. Gate: time, pulses and errors compared to a baseline

Date: 2026-10-24. Status: accepted.

## Context

Promotion must be decided by evidence, not by a calendar. Fedora Bodhi promotes updates by karma and time without negative feedback; Debian promotes packages after a waiting period without release-critical bugs.

## Decision

A feature moves to the next channel when all checks pass: minimum days in the channel, minimum number of pulses, maximum share of broken pulses, and error rate of subscribers with the feature compared to those without it. Failed checks are returned with explanations. A human can force a promotion; it is recorded.

## Consequences

- Pulses about the app in general count for every feature in the channel: early subscribers judge the whole set they run. Feature-specific pulses are more precise and the SDK supports them.
- Error rates compare only subscribers who consented to error collection, in both groups. Without consenting subscribers outside the feature's channels there is no baseline and the check passes.
- Errors may name the feature they come from. Errors of other features are left out, so one broken feature does not hold back healthy ones in the same channel. Unattributed errors count for every feature; the with/without comparison then catches regressions only between channels.
